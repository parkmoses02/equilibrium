# Pendulum Panel (PC)

## 이중진자 운전 화면 (double_upright)

이 폴더의 펌웨어를 PlatformIO 환경 **double_upright → Upload**로 올린 뒤 Monitor를 닫는다.
PC는 Python 3와 Tkinter, pyserial(`python -m pip install pyserial`)이 필요하다.
저장소 루트의 **DoublePanel.pyw**를 더블클릭하거나 `python -m panel.double_console`로 실행한다.
기존 단진자 프로그램과 이중진자 로그 뷰어는 그대로 사용할 수 있지만 USB 포트는 한 프로그램만 연다.

1. COM 포트를 선택하고 연결한다. 이전 펌웨어처럼 DP1이 없는 장치에서는 자세 버튼이 잠긴다.
2. 카트를 물리적으로 중앙에 놓고 두 링크를 DD로 정지시킨 후 **중앙 DD 영점**을 누른다.
3. 목표 DD / DU / UD / UU 중 하나를 누른다. 모터 OFF의 DD 출발은 두 글자(rq/rw/re),
   유지 중 또는 모터 ON의 DD 대기는 한 글자다. 궤적 선택, 출발 허가, 포착, 레일 보호는 펌웨어가 결정한다.
   보드가 출발 대기/전환 중이면 새 목표를 예약하지 않는다. 거절·정지 사유는 화면 아래에서 확인한다.
4. DD는 하강 후 모터 ON 대기다. **즉시 출력 OFF**(!)는 하강 없이 출력을 끄므로 진자가 떨어질 수 있다.
   소프트웨어 정지는 USB 통신이 필요하며 물리 비상 정지를 대체하지 않는다. 연결 해제는 정지 명령이 아니다.
   끊기면 장치 상태를 직접 확인한다. 재연결 시 이전 명령은 전송하지 않는다.

각도는 수직 위가 0°인 **두 절대각**이다. 카트 위치·속도는 TMC5160 내부 램프 추정값이며
가속도는 실측값이 아닌 제한 후 가속도 명령(속도 제한 전)이다. 제어 중 각속도는 EKF 추정값이다.
수신 원문(기존 POSE, 종료 CSV, 정지 코드 포함)은 저장소의 logs/double_panel_*.log에 저장한다.
DP1 형식: 장치시각(µs), 상태, 출발키, 목표키, x(m), base/tip(rad), base/tip 각속도(rad/s),
램프 속도(m/s), 제한 후 가속도(m/s²). 활성 약 20 Hz, 비활성 약 10 Hz; TX 여유가 없으면 생략.
미보정 상태의 수치와 비활성 상태의 속도·가속도 필드는 유효하지 않다.

## 운전 화면과 게인 계산기의 개발 방향

**현재 운전 화면**은 제어기를 변경하지 않고 실험하는 도구다. 장치 그림과 최근 10초 각도 그래프에서 첫 링크는 청록색, 끝 링크는 주황색이다. 먼저 팀 실험에서 목표 버튼을 눌렀을 때 출발 대기, 전환, 포착 후 유지, 거절·정지 사유가 실제 보드와 일치하는지 확인한다. 기존 DU 계산기는 별도 PC 도구이며, 운전 화면에서 보드로 게인을 전송하는 기능은 없다.

**다음 단계**는 자세별로 계산기 네 개를 만드는 것이 아니라, 한 계산기에서 목표 자세를 선택하는 방식이다. 두 글자는 첫 링크와 끝 링크의 **절대 자세**(D: 아래, U: 위)를 뜻한다. 평형점에 따라 선형화한 모델이 달라지므로 같은 Q·R이라도 같은 K를 쓰지 않는다.

| 선택 자세 | 계산·비교할 제어기 | 현재 펌웨어 기준 |
|---|---|---|
| DD | 하강 후 잔류 진동을 줄이는 감쇠 제어 | `K_r` |
| DU | 첫 링크 아래, 끝 링크 위의 자세 유지 LQR | `K_e` |
| UD | 첫 링크 위, 끝 링크 아래의 자세 유지 LQR | `K_w` |
| UU | 카트 위치 오차의 적분까지 포함한 직립 유지 LQI | `K_q`와 `KI_Q` |

통합 순서는 다음과 같다. 아래는 **계획**이며 현재 운전 화면의 기능이 아니다.

1. 자세별 모델, 상태 순서·단위·부호, 기본 가중치를 [펌웨어](../src/double_pendulum/upright.h)와 맞춘다. 기본값으로 현재 게인을 반올림 오차 안에서 재현하는 것을 통합 기준으로 삼는다.
2. 현재 K와 후보 K를 나란히 표시하고, 정지에 가까운 자세에서의 유지뿐 아니라 실제 포착 속도에서 시작한 응답과 속도·가속도 제한 도달 여부도 시뮬레이션으로 비교한다. 이때 바꾸는 것은 **포착 후 제어기**다. 스윙업·다운 도중 사용하는 프레임별 궤적 추종 게인은 별도로 관리한다.
3. 보드에 적용하는 기능은 그 이후에 추가한다. 모터 OFF에서만 명시적으로 적용하고, 보드가 수락한 값 확인과 기존 게인 복원을 함께 제공한다.

## 기존 단진자 패널

Lightweight Python panel to interact with the ESP pendulum firmware.

Requirements
- Python 3.8+
- Install packages from `requirements.txt`:

```bash
python -m pip install -r panel/requirements.txt
```

Run (recommended)

```bash
python -m panel.panel
```

Or run directly (may require Python path adjustments):

```bash
python panel/panel.py
```

Usage notes
- Set the correct serial port in the GUI (e.g. COM3) and click Connect.
- The panel listens for packets in the form `0xAA addr float32` (device->PC).
- To send commands the panel writes 5-byte packets `addr + float32` (PC->device).

This is a minimal starter panel. Extend controls to send specific parameters (addresses are in the source comments).

## Rev.L 이중진자 실시간 표시 (읽기 전용)

1. PlatformIO `double_upright`에서 Upload and Monitor를 실행한다. Monitor가 출력하는 로그 경로를 확인한다.
2. 저장소 루트의 별도 터미널에서 `python panel/live_pose.py`를 실행한다 (Tkinter 필요). 자동 선택이 안 되면 로그 경로를 인자로 지정한다. Monitor를 다시 시작해 로그가 바뀌면 뷰어도 다시 실행한다.
3. 기존 제어 명령은 **PlatformIO Monitor에서만** 입력한다. 뷰어는 COM 포트를 열지 않는다. 동작 중 약 20 Hz로 실제 두 절대각과 램프 기반 카트 **추정** 위치를 그린다. 정지/통신 중단 시 마지막 자세를 고정한다.

## DD에서 UD로 스윙업

카트 위치 보정과 레일 보호는 `rw`, `re`에 적용된다. `rw` 스윙에서는 출발점 대비 궤적 위치 오차에 해당 프레임 위치 게인의 50%를 적용하며 보정은 ±1 m/s²로 제한한다. 두 경로 모두 캐치 후에는 `z` 중앙에 대한 위치 보정을 ±1.5 m/s² 범위에서 적용한다.

출발 전에는 현재 위치에서 전체 기준 궤적의 제동 여유를 검사한다(`RAIL_START_MARGIN`). 동작 중에는 현재 램프 위치와, 램프 속도 및 직전 명령 속도로 각각 계산한 예상 정지 위치를 검사한다. 하나라도 ±28 cm에 닿으면 속도 0을 명령하고 램프 정지를 확인한 뒤 `RAIL_BRAKE`로 종료한다. 500 ms 내에 정지를 확인하지 못하면 `RAIL_BRAKE_TIMEOUT`이다. 로그에는 제동 시작 및 종료 위치와 램프 속도가 기록된다. 예측에는 20 ms 지연과 4 m/s² 감속을 가정하고 제동 명령은 8 m/s²를 사용한다. 실제 제동거리와 탈조는 별도 실측이 필요하다. ±30 cm 초과 정지와 `x` 수동 정지도 적용된다.

1. `double_upright` 모니터에서 카트를 중앙에 두고 두 링크를 아래로 늘어뜨려 정지시킨 뒤, `z`를 입력해 영점을 저장한다.
2. `rw`를 한 줄로 입력한다. DD 자세와 드라이버 점검을 통과하면 5 ms마다 DD→UD 궤적을 추종한다. 처음 720프레임(3.60초)은 스윙, 마지막 24프레임(0.12초)은 UD를 목표로 잔류 운동을 줄이는 구간이다.
3. 궤적이 끝난 직후 두 엔코더의 정상 측정 프레임에서 캐치를 판정한다. 베이스는 수직 위, 팁은 수직 아래를 기준으로 각각 각도 오차가 0.10 rad 이하여야 한다. 두 링크 각각의 필터링된 절대각속도 크기는 0.50 rad/s 미만, 카트 램프 속도 크기는 0.30 m/s 이하여야 한다.
4. 모두 만족하면 `CATCH UD -> w`를 출력하고 UD 유지 제어로 전환한다. 하나라도 벗어나면 측정값과 `OFF: missed UD; no retry`를 출력하고 모터를 끈다. 동작 중에는 `x`로 정지할 수 있다.

UD 궤적의 오프라인 검증은 저장소 루트에서 `node simulation/dd-uu/verify.js ud`로 실행한다.

## DD에서 UU로 스윙업

일반 `double_upright`의 모니터에서 카트를 중앙에 놓고 두 링크를 아래로 늘어뜨린 후 `z`를 입력한다. 두 링크를 정지시킨 상태에서 `rq`를 한 줄로 보내면 DD→UU 궤적을 한 번 실행한다. `x`로 정지할 수 있다. `re`는 DD→DU 명령이다.

744개 명령 프레임(각 5 ms) 직후 한 번 캐치를 검사한다. θ는 두 링크의 수직 위쪽 기준 각도 오차 절댓값 중 큰 값, ω는 두 필터링된 각속도 절댓값 중 큰 값, v는 카트 램프 속도의 절댓값이다. 다음 두 경우 중 하나이면 캐치한다.

- 기본 범위는 θ ≤ 0.05 rad, ω < 0.50 rad/s, v ≤ 0.20 m/s이다.
- 확장 범위는 두 링크의 각도 차이 ≤ 0.01 rad, ω ≤ 0.05 rad/s이고 `θ / 0.10 + v / 0.30 ≤ 1`인 경우다.

카트 위치 판정은 `rw`, `re`, `rq`, `p` 모두 마지막 `z`를 기준으로 한다. 좌우 어느 쪽이든 300 mm를 초과하면 시작을 차단하거나 동작 중 정지한다. 스윙과 유지 제어는 진자의 각도·각속도와 카트 속도를 사용한다. 위치는 TMC5160의 램프 카운터로 추정하므로 손으로 카트를 옮기거나 탈조가 생기면 카트를 중앙에 놓고 두 링크를 늘어뜨린 뒤 `z`를 다시 입력한다.

UU 캐치에 성공하면 `CATCH UU -> q`와 함께 UU 유지 제어로 전환한다. 캐치 실패 시 측정값과 `OFF: missed UU; no retry`를 출력한다. 유지 중 어느 한 링크의 오차가 0.17 rad를 넘으면 정지한다.

오프라인 검증은 저장소 루트에서 `node simulation/dd-uu/verify.js`로 실행한다. UU 궤적을 다시 설계하는 스크립트는 `simulation/dd-uu/design.py`에 있다. 일반 보드 빌드에는 최적화 도구가 필요하지 않다.

### 엔코더 오류가 한 번 발생한 경우

스윙과 유지 중 HEDS 한 채널에서 A/B 두 비트가 동시에 바뀐 것으로 관측되면 해당 관절의 직전 각도와 각속도로 한 제어 주기(통상 5 ms)의 각도를 추정한다. 다른 채널은 현재 측정값을 사용한다. 정지해 카운트가 같은 프레임은 정상이다. CSV의 `estimated_heds`는 0이면 두 채널 모두 측정값, 1 또는 2이면 해당 HEDS 채널의 추정값을 사용했다는 뜻이다.

한 프레임에 여러 오류가 있거나 직전 오류 후 50 ms 이내에 다시 발생하면 정지한다. 캐치 프레임에 단발 오류가 있으면 다음 정상 프레임에서 캐치를 판정한다. 원시 카운트에는 누락이 남을 수 있어, 오류가 있었던 회차가 끝나면 카트를 중앙에 두고 두 링크를 늘어뜨린 뒤 `z`로 다시 영점을 잡는다.

### 캐치 진입값과 정지 코드

`rw`, `re`, `rq`가 캐치에 성공하면 진입 프레임을 RAM에 보관한다. 동작 종료 후 CSV 출력이 끝나면 `CATCH_ENTRY` 한 줄에 자세, 스윙 시작 후 경과 시간(µs), 베이스·팁의 절대각과 목표 오차(°), 두 링크의 필터링된 각속도(rad/s), 카트 램프 속도(m/s)를 출력한다. 속도와 각도는 부호를 포함한다. PlatformIO의 `log2file` 모니터를 사용하면 이 줄도 회차 로그에 저장된다.

종료 출력의 마지막 줄은 `STOP_CODE=...`이다. 예를 들어 `REPEATED_ENCODER_EDGES`는 동작 중 엔코더 오류 정지, `TILT_LIMIT`는 유지 중 기울기 한계 초과, `MANUAL_STOP`은 `x` 입력, `TRACE_COMPLETE`는 기록 시간 종료를 뜻한다. 엔코더로 정지한 회차의 `Frame errors`는 정지 프레임의 채널별 오류 수이고, `invalid_since_z`는 마지막 영점 설정 이후의 누적 수다.

## 이중진자 실험 재생

저장소 루트에서 `python -m panel.replay`를 실행하거나 대시보드의 **실험 재생** 탭을 연다. 최근 기록이 열리며 **로그 열기…**로 다른 파일을 고를 수 있다. 회차를 선택하고 **재생**을 누른다. 시간 막대와 배속으로 원하는 구간을 살펴볼 수 있다.

두 링크는 위쪽을 0°로 한 절대각으로 그린다. 카트 위치는 드라이버 램프 추정값이다. 저장된 스윙 CSV와 시리얼 자세 기록을 사용하며, 표본 사이에는 직전 자세를 표시한다. 특정 파일을 열려면 `python -m panel.replay "logs/파일명.log"`를 사용한다.

## DU 이중진자 LQR

`python -m panel.panel`에서 **DU 이중진자 LQR** 탭을 연다. 실시간 자세 뷰어에서도 같은 이름의 버튼으로 열 수 있다. 계산기만 실행하려면 저장소 루트에서 `python -m panel.du_lqr`를 실행한다.

Q의 여섯 대각 성분과 가속도 입력 가중치 R을 편집하면 DU 모델의 이득 K가 즉시 갱신된다. 계산은 PC에서만 수행하며 보드 연결 없이 사용할 수 있다. 계산 결과를 현재 보드의 설정값으로 간주하지 말고, 해당 펌웨어 버전의 `K_e`와 비교한다.

## 실험 후 외란 분석

성공 회차의 `RE_CSV_BEGIN`부터 `RE_CSV_END`까지 한 블록을 텍스트로 저장한 뒤
`python simulation/dd-du/inverse_residual.py run.txt` (NumPy, SciPy)를 실행한다.
같은 기준 궤적 헤더를 사용해야 한다. 결과는 램프 가속도를 실측 대신 사용한 **등가 토크 잔차**이며,
관절 마찰의 독립 측정값이나 포착 이후 유지 구간 분석이 아니다.
